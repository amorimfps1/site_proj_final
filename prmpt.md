# MEGA PROMPT DEFINITIVO — ACADEMIC OS
## Dashboard Acadêmico Premium | HTML, CSS e JavaScript Puro

# 1. SUA MISSÃO

Atue simultaneamente como:

- Principal Product Designer especializado em softwares SaaS.
- Senior UI/UX Designer com experiência em design systems.
- Senior Front-End Engineer.
- Creative Developer especializado em interfaces interativas.
- Especialista em visualização de dados e usabilidade.
- Diretor de arte digital responsável pela identidade visual do produto.

Desenvolva uma aplicação chamada **Academic OS**, um dashboard acadêmico premium para acompanhamento de notas, frequência, disciplinas, tarefas, avaliações e desempenho universitário.

A aplicação deverá utilizar EXCLUSIVAMENTE:

- HTML5 semântico.
- CSS3 moderno.
- JavaScript Vanilla ES6+.
- SVG e Canvas nativos, quando necessário.
- localStorage para persistência.

Não utilize React, Vue, Angular, Next.js, Tailwind, Bootstrap, jQuery, bibliotecas de gráficos ou frameworks.

O projeto precisa funcionar localmente, sem instalação de dependências e sem servidor obrigatório.

## OBJETIVO VISUAL ABSOLUTO

**O resultado NÃO pode apresentar os padrões visuais, textuais e estruturais característicos de sites gerados automaticamente por inteligência artificial.**

Quero uma interface com identidade própria, decisões de design conscientes, hierarquia visual inteligente, espaçamentos naturais, conteúdo objetivo e acabamento profissional.

Não basta criar uma interface bonita. É necessário criar uma interface que pareça ter passado por pesquisa de produto, prototipação, revisão de design, implementação e refinamento.

O resultado esperado é um software que poderia ser lançado comercialmente.

# 2. PRINCÍPIO FUNDAMENTAL — DESIGN HUMANO, NÃO GENÉRICO

Antes de escrever qualquer código, defina internamente uma direção de arte consistente para a aplicação.

Cada decisão visual deverá ter uma justificativa funcional.

Não adicione componentes apenas para preencher espaços.

Não adicione textos apenas para explicar informações óbvias.

Não adicione ícones apenas porque existe espaço disponível.

Não adicione animações apenas para mostrar sofisticação técnica.

Não adicione gráficos apenas para deixar a tela mais preenchida.

Não transforme todas as informações em cards.

Não aplique o mesmo padrão visual em todas as seções.

**Uma interface profissional não é aquela que possui mais elementos. É aquela em que cada elemento está no lugar certo.**

A aplicação precisa demonstrar:

- Personalidade visual.
- Hierarquia intencional.
- Consistência entre telas.
- Variação controlada de composição.
- Economia de elementos.
- Precisão nos alinhamentos.
- Clareza da informação.
- Densidade informacional equilibrada.
- Componentes realmente necessários.
- Interatividade funcional.

Evite qualquer aspecto de template genérico ou apresentação conceitual de portfólio.

# 5. REGRA CRÍTICA — ELIMINAR A APARÊNCIA DE IA

Esta seção tem prioridade máxima em todas as telas.

## 5.1. Não criar cards repetitivos

Um dos principais problemas de dashboards genéricos é a repetição de cards visualmente idênticos.

Evite:

- Todos os cards com a mesma altura.
- Todos com o mesmo ícone no canto superior.
- Todos com um título pequeno.
- Todos com um número gigante.
- Todos com uma descrição abaixo.
- Todos com um badge colorido.
- Todos com o mesmo espaçamento interno.
- Todos com a mesma decoração.

Isso cria uma interface mecânica.

Em vez disso, utilize **variação composicional intencional**:

- KPIs compactos para indicadores simples.
- Painéis maiores para gráficos.
- Listas para informações operacionais.
- Tabelas para conjuntos de dados.
- Barras para comparações.
- Indicadores circulares somente quando úteis.
- Cards detalhados para disciplinas quando fizer sentido.

A diferença entre os componentes deverá surgir da função de cada um, e não de decoração arbitrária.

## 5.2. Reduzir drasticamente textos desnecessários

Não quero comentários visuais em cada componente.

Exemplo ruim:

"Média geral"

"Acompanhe o desempenho acadêmico ao longo do semestre e veja como suas notas estão evoluindo."

Exemplo correto:

"Média geral"

"8,4"

A informação já é autoexplicativa. Não é necessário escrever um parágrafo.

Outro exemplo ruim:

"Tarefas"

"Gerencie suas atividades, acompanhe prazos e mantenha sua produtividade acadêmica organizada."

Exemplo correto:

"Tarefas"

"5 pendentes"

**Regra:** uma informação não precisa de uma descrição quando seu título, contexto e representação visual já são suficientes.

Microcopy deve existir somente quando melhora a compreensão ou ajuda o usuário a tomar uma decisão.

## 5.3. Proibir símbolos repetidos

Evite a repetição excessiva de:

- `·`
- `•`
- `|`
- `/`
- `—`
- `→`
- `✦`
- `✧`
- `●`

Não utilize esses caracteres sistematicamente para separar informações.

Exemplo ruim:

"Banco de Dados · 3º semestre · 60h · Professor Carlos · Em andamento"

Exemplo melhor:

**Banco de Dados**

60h

Em andamento

Organize informações secundárias por alinhamento, proximidade, colunas ou hierarquia tipográfica.

Não substitua um excesso de símbolos por outro.

## 5.4. Não criar badges para tudo

Badges devem identificar situações relevantes.

Utilize badges para:

- Risco acadêmico.
- Tarefa atrasada.
- Prioridade urgente.
- Situação da disciplina.
- Estado de conclusão quando necessário.

Não utilize badges para informações normais que poderiam ser apenas texto.

Não coloque badges em todos os títulos.

Não crie badges como "Ativo", "Online", "Atualizado" e "Disponível" quando não houver necessidade funcional.

Um badge perde significado quando tudo na interface é um badge.

## 5.5. Não repetir a mesma estrutura em todas as páginas

Cada seção precisa de uma arquitetura de informação adequada.

- Visão geral: indicadores, gráfico principal e resumo operacional.
- Notas: tabela, filtros, cálculos e evolução.
- Frequência: indicadores de presença, histórico e risco.
- Tarefas: lista, Kanban e calendário.
- Disciplinas: visão resumida e detalhes.
- Relatórios: análises e comparações.

Não transforme cada página em quatro cards superiores seguidos por dois gráficos e uma tabela.

Isso torna a aplicação previsível e artificial.

## 5.6. Não utilizar microtextos genéricos

Evite frases como:

- "Sua jornada começa aqui."
- "Tudo o que você precisa em um só lugar."
- "Transforme seus dados em resultados."
- "Explore todo o seu potencial."
- "Seu sucesso é nossa prioridade."
- "Bem-vindo à sua experiência inteligente."
- "Insights poderosos para decisões melhores."
- "Gerencie tudo de forma simples e eficiente."

Essas frases soam como conteúdo de marketing gerado automaticamente.

Utilize linguagem natural e direta.

Exemplos adequados:

- "Boa noite."
- "Visão geral"
- "Média do semestre"
- "Próximas entregas"
- "Nenhuma tarefa pendente"
- "Frequência abaixo do mínimo"
- "Adicionar avaliação"
- "Nota registrada"
- "Alterações salvas"

A interface precisa falar como um produto real, não como uma apresentação comercial.

# 6. TIPOGRAFIA COM ACABAMENTO PROFISSIONAL

A tipografia deve ser um elemento central da identidade visual.

Defina uma escala tipográfica consistente, mas não aplique o mesmo tamanho e peso indiscriminadamente.

Diretrizes:

- Título principal: aproximadamente 26–30px.
- Títulos de seção: 16–20px.
- Títulos de cards: 13–15px.
- Texto comum: 13–14px.
- Informações auxiliares: 12–13px.
- Números de KPIs: 28–36px.

Ajuste a escala quando necessário.

Utilize números tabulares para notas, porcentagens e tabelas.

Evite:

- Texto em caixa alta em todos os lugares.
- Fontes extremamente arredondadas.
- Pesos muito fortes em todas as informações.
- Títulos desnecessariamente grandes.
- Letras excessivamente espaçadas.
- Mistura indiscriminada de famílias tipográficas.
- Textos secundários com contraste insuficiente.

A interface deve ter hierarquia pela tipografia, não pela quantidade de cores.

# 7. ESPAÇAMENTO E COMPOSIÇÃO

Utilize um sistema de espaçamento consistente com valores como:

4, 8, 12, 16, 20, 24, 32 e 40px.

Entretanto, não aplique espaçamento de maneira mecânica.

O espaçamento deverá considerar:

- Relação entre título e conteúdo.
- Agrupamento de informações.
- Prioridade visual.
- Densidade informacional.
- Tamanho disponível.
- Contexto de navegação.

## Regras

Não centralize tudo.

Não deixe todas as seções com margens gigantes.

Não aplique padding de 24px indiscriminadamente em todos os componentes.

Não utilize largura fixa para elementos que devem ser fluidos.

Não deixe gráficos pequenos dentro de cards enormes.

Não coloque um card dentro de outro card sem necessidade.

Evite excesso de contêineres aninhados.

Em telas densas, prefira uma composição mais compacta.

O objetivo é criar uma aplicação com excelente aproveitamento de espaço, mas sem comprometer a legibilidade.

# 28. REVISÃO CRÍTICA ANTI-IA

Após implementar a aplicação, execute uma revisão visual rigorosa de todas as páginas.

- Botões sem função.
- Filtros que não filtram.
- Gráficos que não refletem os dados.
- Modais meramente ilustrativos.
- Menus vazios.
- Notificações inventadas.
- Indicadores estáticos.
- Animações que prejudicam o fluxo.
